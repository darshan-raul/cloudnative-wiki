## Approach and result

The previous consolidation removed too much useful learning structure. This pass restored service diagrams, tables, concrete input/output examples, operational sequences, monitoring/tuning, comparisons and original cross-wiki footers. Corrected current prose, lifecycle warnings, primary references and new-topic links remain. Where the original API/claim was invalid, the replacement retains the learning objective with real fields or a detailed supported workflow rather than relabeling fabricated code as runnable.

Aurora specifically restores distributed architecture/quorums, engine/compute comparison, endpoint caveats, verified-version cluster→writer→reader creation with availability waits and DBClusterMembers.IsClusterWriter verification, failover/global/backtrack operations and a worked 400 ACU-hour scenario. Original Azure/GCP/PostgreSQL links and owning create-operation references are present.

DynamoDB's valid original core/create/CRUD/batch material was recovered, with reserved-name alias correction and explicit unprocessed-batch handling. Other heavily erroneous original sections were rebuilt at meaningful depth. Retired QLDB/Kinesis SQL retain history, architecture, semantic comparisons and migration/test plans rather than active deployment commands. Duplicate database Redshift remains an application view; the canonical analytics lesson now contains table design, loading/export, security, WLM/sharing, monitoring and recovery detail.
