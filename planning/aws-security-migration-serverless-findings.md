### Additional Lambda checks

- **R16:** `serverless/lambda/README.md` recommends moving a VPC-connected function to a public subnet as a cold-start remedy. This does not remove VPC networking or give the function public-IP internet access. [VPC internet access](https://docs.aws.amazon.com/lambda/latest/dg/configuration-vpc-internet.html).
- **R17:** Both Lambda runtime catalogs list managed Go 1.x and other deprecated runtimes without lifecycle context. Distinguish invocation from creation/update restrictions, custom runtimes and image ownership. [Runtime lifecycle](https://docs.aws.amazon.com/lambda/latest/dg/lambda-runtimes.html).
- **R18:** Lambda/serverless/SAP quota claims need mode scope: current async payload maximum is 1 MB, not 256 KB; standard timeout is 15 minutes, while Managed Instances support up to 90 minutes for documented async/event-source cases. Add the advanced branch without replacing standard Lambda behavior. [Lambda quotas](https://docs.aws.amazon.com/lambda/latest/dg/gettingstarted-limits.html).

## Remaining source and example gaps

These are material suspect claims or missing teaching topics to resolve before calling these notes deployment-ready:

- ACM: fabricated DigiCert issuer/payments narrative, private DNS-validation requirement, renewal timing/key algorithms, 25,000-certificate quota and cross-region copies. Include Amazon Trust Services, certificate-type/algorithm restrictions, region ownership, imported-certificate renewal responsibility and exportable-public lifecycle.
- CloudTrail: “every AWS action” overpromises event coverage; Lambda classified as global; fixed two-events-per-S3-operation assertion; duplicate trail/data/Insights/Lake pricing differences; S3 interval confused with guaranteed CloudWatch real-time delivery. Scope actions, selectors, exclusions and delivery latency. Preserve security requirements when recommending disabling logs to save money.
- Config: all-resources/every-change overpromise; same-region S3 bucket rule, invented recording quotas, global IAM region exclusions, periodic/change-trigger rule distinctions, aggregator read-only scope and remediation permissions. Add a complete recorder/delivery-channel/rule/remediation test, not disconnected commands.
- Detective: tariff/free-tier/retention/member-count rows, source-package scope and fictional finding names need owning references. Investigation is useful but process/CPU views cannot be promised solely from API/VPC data. Add a realistic investigation scenario and Organizations auto-enrollment rules.
- GuardDuty: invented “Enterprise” product tier, free management-log tier and flow-log GB-versus-entry arithmetic; IP/threat-list quotas, modern protection-plan coverage and Critical findings. Verify actual update-detector/malware API shapes and protection-specific IAM roles. Do not recommend selective bucket monitoring without checking product controls.
- Macie: first-10-GB-free and free-policy-monitoring rows, job quotas and “continuous per-object trigger” need current pricing/workflow sources. Teach automated discovery sampling versus scheduled jobs, supported formats/encryption, exclusions, sampling limits, identifiers, findings and remediation authorization.
- Secrets Manager: replica fees, versions/staging labels/rate quotas are not universal. Rotation template needs real `ClientRequestToken`, `AWSPENDING`, DB update, test and stage transfer rather than placeholder steps; show rollback, secret caching, cross-account KMS policy and logging avoidance. Managed database rotation and Lambda rotation must be distinguished.
- Security Hub: current Security Hub versus CSPM product boundaries, aggregation/ingestion/check pricing, standards/check identifiers, regional central configuration and integrations require a current-version pass. Finding-resolved status is not resource remediation; keep that correct caveat. Cross-reference canonical security notes instead of duplicating incompatible quota/pricing advice.
- Migration hubs: 6 Rs omits Relocate relative to SAP's 7 Rs; near-zero downtime lacks consistency/cutover conditions. “DMS full month even for two weeks,” CDC credits and stepped DataSync tariff are unsupported. Distinguish burstable CPU credits from CDC backlog and actual metered lifetime.
- Application Discovery: invented SQL query API, fixed 90-day retention, collector capability/platform/Region limitations and installation contracts need source checks. Agentless Collector, old Connector and Migration Evaluator collector are not interchangeable.
- Migration Evaluator: VMware-only OVA, agent-based assessment and automatic 6-R classification look conflated with ADS. Validate collection/API workflow; assess observed peaks, licensing, support, network, storage and migration effort rather than CPU-average-only sizing.
- SMS: contradictory do-not-run-two-agents versus run-both advice, historical agentless connector described as an agent, VMware-only/Hyper-V table and continued-availability claims. S108 confirms a GovCloud discontinuation notice; don't assert a global exact date without its owning source.
- MGN: fictional lifecycle enums/options/install instructions, automated source shutdown, per-server-hour pricing from first use, post-cutover cleanup and cross-Region prohibitions need actual API/lifecycle sources. Add test-network isolation, dependencies, source-write quiescence, finalization, rollback and cost cleanup.
- DataSync: invalid `VerifyMode=OVERWRITE` in migration hub; changing VerifyMode to NONE does not establish a correct same-size-change detection strategy; claimed data-format conversion is unsupported. Agent CPU/RAM requirements, transfer modes, object/file limits, bandwidth units, Basic/Enhanced pricing and API option structures require direct sources. The verification/metadata task is not an ETL transformation service.
- DMS: Oracle “AWS XDB” reader, ORC target support, replication-class catalog, stop-replication-instance advice, schema conversion and table-creation scope, PostgreSQL slot/WAL retention, validation activation and tuning-property names need contracts. A row count alone is not data correctness. Add LOB handling, primary keys, DDL changes, source permissions, CDC retention, lag acceptance, validation and rollback.
- Batch: strict-order scheduler assumption omits fair-share/dependency/resource placement; retry status strings need real examples; typo on one-hour timeout warning contradicts infinite-default statement; array size does not guarantee simultaneous execution. Show service/task roles, image pull/log setup, compatible Fargate resources and EC2/MNP distinction. Current resource quotas/version-specific fields need source references.
- Lightsail: obsolete IPv4/IPv6 bundle rates, unsupported managed MongoDB, $5 managed DB/$10 LB examples, max-resource limits and one-sided EC2 comparison need correction. Container services are not “Kubernetes-lite”; illustrate multi-container and scale/network constraints from actual product docs.
- App Runner: source deployment directly contradicts hub's Dockerfile-required claim; ECS autoscaling called manual; Lambda image support contradicted in table; fractional CPU/memory/quotas and active-versus-provisioned pricing omitted. At two average instances, the one-instance $89 subtotal cannot remain the average. Provide complete creation IAM roles, endpoint access, health, scaling test and pause/delete cleanup.
- API Gateway: IAM omitted from HTTP auth; gRPC claim unsubstantiated; JWT-dependent HTTP tariff invented; cache billed per-request/per-GB across duplicate notes; WebSocket authorizer applicability and `$connect` behavior need detail. Examples need actual resource/method IDs, integration URI, Lambda permission, deployment/stage and invoke test. Teach API key versus auth, request validation, CORS, private integration/endpoints, errors/access logs and quota discovery.

## Teaching disposition

These service pages offer useful orientation, but the consistently unsourced “Limits,” pricing and “Nuggets & Gotchas” need replacement or validation. Core security/migration lessons should include a complete, least-privilege, reversible lab with expected evidence and failure handling. Pending bullets are explicitly part of the remediation research queue, not evidence that every flagged assertion is false.
