# AWS notes gap audit

Audit date: 2026-10-12. This is the preserved **pre-remediation baseline**: counts, findings and line anchors below describe the original 155-note corpus. Statements about unchanged published content refer to that capture, not the current worktree. Follow [remediation progress](aws-remediation-progress.md) and [verification](aws-remediation-verification.md) for the implemented changes and current 181-note corpus.

## Scope and evidence

The core corpus is `content/AWS.md` plus all Markdown files under `content/AWS/`: **155 notes**. [The inventory](aws-audit-inventory.md) lists every note and its reference/code indicators. AWS material under `AI/aws/`, `Security/cloud-security/aws/`, and `Kubernetes/eks/` is checked for existing coverage and duplicate ownership; it is not included in the 155-note count. An EKS topic already taught under `Kubernetes/eks/` is a navigation/consistency gap, not an absent topic.

The scope covers five requested dimensions: missing notes, missing topics within existing notes, incorrect information, learning quality, and missing references. “All gaps” is assessed against the existing AWS architecture/service scope, its SAP-C02 curriculum promise, and AWS Well-Architected guidance; it does not mean creating a page for every AWS product. Expansion priorities below are editorial judgments, not assertions that AWS requires a separate Markdown page for each service.

Evidence collected:

- `node scripts/check-content.mjs AWS --verbose`: zero structural errors, one stub warning (Data Lifecycle Manager). The validator resolves links against the whole vault. It does not verify AWS behavior, ordinary Markdown links, external URL availability, or example correctness.
- Inventory: 46 notes with no external URLs; 49 with no AWS documentation URLs. Homepage/pricing links alone do not provide references for detailed behavior. Counts are URL occurrences, not availability checks.
- `node planning/aws-audit-snippets.mjs`: 611 fenced JSON/Python/shell blocks checked without executing them; 24 parse failures. Some failures are intentional fragments or Dev Tools requests and must not be counted as 24 broken programs.
- Local AWS CLI 2.34.48 input skeletons were inspected for selected API contracts. No AWS resource operations were run.
- [Reference availability](aws-reference-availability.md): 30 observed 404s and six access-denied URLs kept separate from confirmed failures.
- [Primary-source verification](aws-source-verification.md) supplies independent confirmed factual findings and links to AWS documentation. Its S-series IDs are part of this audit.

The previous `wiki-audit-gaps-and-expansions.md` is historical evidence, not the current baseline. Its AWS counts, empty certification landing page, directory links, and ghost-stub descriptions no longer match the worktree. `aws-progress.md` also names files already moved/deleted and marks reference work complete where references are absent.

## Priority order

1. **P0:** Correct security/networking advice that changes access or breaks connectivity; remove retired services from current deployment recommendations; repair fabricated API contracts and billing models.
2. **P1:** Make core examples reproducible, repair pricing arithmetic, add direct references, and fill foundation/operations/identity/backup/delivery coverage.
3. **P2:** Add guided labs and scenario reasoning, consolidate duplicate notes, improve discovery and metadata, then add specialist breadth.

The largest quality problem is unsupported specificity. Many notes have useful introductions, tables, and commands, followed by confident but wrong “Nuggets & Gotchas,” quota tables, or price scenarios. Increasing note length alone will not address this.

## Reference gaps

The inventory is the exact per-file list; this section groups the findings for action.

- **25/25 SAP notes:** no external references. Add the current official exam guide to the landing page and task-specific service/architecture references to each task note. The domain indexes can point to the common guide and sourced lessons without redundant bibliographies.
- **Migration:** DMS, DataSync, Migration Evaluator and SMS have zero URLs despite hundreds of lines of examples. Application Discovery and Application Migration have external links but zero AWS documentation URLs. Deep-link API/lifecycle sources and prescriptive migration guidance.
- **Analytics:** Lake Formation, analytics hub and Kinesis hub lack external URLs. Lake Formation particularly needs permission-model and cross-account references; the Kinesis hub needs the SQL discontinuation and Firehose rename sources.
- **Identity/network concepts:** external IDs, role types, delegated administrators, API Gateway usage plans, VPN, VPC Lattice, magic IPs and App Mesh comparison have no external references. Add direct sources for the security properties and lifecycle status rather than another homepage.
- **Costs:** CUR, RDS/EFS cost notes and concepts/cost-management have no references. Other cost notes often have generic product/pricing links but unsupported formulas and billing guarantees.
- **General entry notes:** AWS hub and cloud-architect-areas have no external references. An index does not need to source every service synopsis independently, but its claims of complete coverage and fixed template guarantees need correction; link the learning scope/primary framework.
- **Patch Manager:** has external references but no AWS documentation URL; add official patch-baseline, maintenance-window, operating-system and compliance limitations beside relevant claims.

Required source quality: a behavior/quota/API/lifecycle claim should point to its owning documentation page; a rate should identify region/operation/date and billing unit. Keep official best-practice guidance distinct from editorial advice, and legacy API names distinct from currently available products. An HTTP 200 does not establish that a source supports its surrounding claim.
