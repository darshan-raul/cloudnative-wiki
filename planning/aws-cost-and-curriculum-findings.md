## Additional wrong-model candidates requiring owning-source checks

- DynamoDB cost note: fictitious 6–12-month On-Demand billing lag; backups priced as direct S3 classes; DAX minimum three nodes plus 30-day reservation; GSI every-write billing; provisioned versus On-Demand rate/quantity arithmetic. A 100-RCU table cannot be offered as equivalent to 50 million reads/day without consistency/item-size/cache/traffic assumptions.
- EBS cost note: invented `io3`; 10,000 gp3 IOPS claimed fully included; obsolete max-performance values; stop versus terminate volume deletion; customer-key references claimed to prevent snapshot deletion; EBS described as SSE-S3; KMS key fees conflated with per-volume fees; c5 called non-Nitro. Reconcile with the storage source supplement rather than retaining contradictory tables.
- Network cost note: same-Region VPC peering claimed free irrespective of AZ; ALB stop/Instance Scheduler support; incorrect LCU/NLCU descriptions; Direct Connect per-minute versus port-hour; charged gateway endpoints; CloudFront origin fetch incorrectly charged S3 egress, contradicting the S3 cost note. Re-price service-specific paths and preserve reliability requirements when recommending AZ consolidation.
- Allocation/Organizations notes: tag policies claimed to require every resource be tagged/inherit parent tags; invented Lambda DLQ `tag: true`; SCPs described as dollar-budget evaluation; undocumented universal 3/7/10% spend tiers; Free Tier per-account promises need account-cohort and organization eligibility checks.
- RI notes: regional/zonal size flexibility is reversed (S20); normalized units are wrong; Convertible sale claims contradict their own no-sale section; all RI services treated as capacity reservations; RDS standby said free under one primary reservation; scheduled dev workloads recommended SP as though unused hourly commitments disappear; ASG instance churn wrongly described as consuming an RI purchase.
- S3 cost note: Intelligent-Tiering archive tiers treated as automatically enabled, small-object semantics and minimum duration conflated; Glacier Flexible/Deep Archive rate rows unsourced; RTC written as every-object 15-minute guarantee; Select recommended without customer-availability caveat; Storage Lens and Storage Class Analysis conflated; lifecycle scenarios count one population in multiple classes simultaneously.
- Cost automation examples need event-contract validation: CAD's payload versus generic event shape, missing imports, pagination/Region scope, cloud-init/idle detection implementation, backup references, permissions, dry-run, audit log and circuit breakers. Custom CloudWatch metrics do not automatically become Cost Explorer billing data. A rate expression is not a midnight-UTC schedule; cron/EventBridge Scheduler timezone behavior must be distinguished.

## SAP-C02 learning and currentness gaps

All 25 certification notes lack external references. The domain percentages and task skeleton are useful, but the landing page promises a curriculum/high score while most tasks are brief service-selection lists. Add official task knowledge/skills mapping, prerequisite service lessons, design scenarios, trade-offs, failure/cost calculations, answer rationale and hands-on drills. Keep the short pages as revision sheets if that is their intended role.

Specific evidence from full prose review:

- Task 1.4: the blanket inability to share security groups via RAM needs current VPC-sharing verification; organization-trail creation must include delegated-admin capability rather than management-account-only language. Malformed escaped bold text (`*Benefits**`) is a visible drafting defect.
- Task 1.5: Cost Explorer history is stale; Compute Optimizer scope omits later resource types; paid memory metric collection and workload-specific evidence need explanation.
- Task 2.1: OpsWorks Chef/Puppet recommended as a current answer despite lifecycle uncertainty; CodeCommit availability needs date/cohort context. “Instant rollback” by DNS is not a guarantee because of caching and client behavior.
- Task 2.4: SNS ordering/persistence table ignores FIFO/archive options; SQS throughput is stale; Lambda 6-MB limit lacks sync/async/streaming distinctions; lifecycle hooks occur at transitions, not necessarily before the OS starts.
- Task 2.5: DAX “no code changes required” hides client/endpoint integration. ElastiCache overview omits Valkey and serverless; placement-group seven-per-AZ statement needs rack/host-level scope.
- Task 2.6: Intelligent-Tiering minimum storage duration stated as 30 days is suspect; auto archive activation and retrieval latency need precise tier distinctions.
- Task 3.1: Session Manager logging must identify SSH/port-forwarding limitations; modern OTel/ADOT and cross-account telemetry missing.
- Task 3.2: Inspector mixes classic/new assessment terminology, omits Lambda and agentless EC2 choices; compare current service coverage with the Inspector note.
- Task 3.3: Compute Optimizer inference confused with ML inference instance selection; Global Accelerator IP-count statement must distinguish address family and standard/custom-routing configurations.
- Task 3.4: WAF “must use ALB or CloudFront” ignores API Gateway/AppSync and other supported associations; ALB static-address needs can use NLB/accelerator fronting with trade-offs, not a simplistic exclusive selection.
- Task 3.5: CUR format described as CSV-only; legacy versus CUR 2.0/Data Exports and Parquet should be linked.
- Tasks 4.1/4.2: discovery/Migration Hub/SMS, Snowcone/Snowball/Snowmobile and VMware product lifecycle need a current-source pass. Do not replace one unverified lifecycle claim with another.
- Task 4.3: storage table has a six-column header/separator for four-column rows, incorrectly puts HDD/SSD in Lustre's use-case cell, and describes EBS as iSCSI-like rather than teaching its actual EC2 attachment model. The structural validator missed this; rendering review is needed.
- Tasks 4.3/4.4: compute/database decisions need licensing, compatibility, conversion effort, state consistency, cutover/rollback and operations scenarios rather than “managed equals better.”

The bullets above distinguish source-confirmed F-series corrections from suspect curriculum claims. These open verification items are part of the audit backlog; they must not be presented as a source-certified corrected syllabus.
