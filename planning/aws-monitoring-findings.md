Additional concrete teaching/contract gaps:

- `cloudwatch-metrics/README.md:37`: ALB metrics namespace is written `AWS/ALB`; check against `AWS/ApplicationELB` throughout metrics/alarms examples. The Python PutMetricData example uses `datetime` without importing it; the `SEARCH` expression is malformed and metric-math example references undefined `m1`/`m2`.
- `cloudwatch-logs/README.md:175`: cross-account subscription example lacks a filter name/valid destination, uses nonexistent `--distribution-field`, and draws log-group-to-log-group delivery instead of explaining destination/stream/role policies. It cannot reproduce the architecture. Source: [subscription API](https://docs.aws.amazon.com/cli/latest/reference/logs/put-subscription-filter.html).
- `cloudwatch-insights/README.md:212`: “top contributors” query sorts `count()` without a `stats ... by src_ip` aggregation. The proposed Contributor Insights JSON also needs its own schema, separate from query language. No fixture/expected results are supplied.
- `cloudwatch-dashboards/README.md:229`: shell fence contains unpaired JSON/output; `cloudwatch:CrossAccountLink` is an unsupported-looking permission and needs replacement with actual OAM or legacy dashboard role configuration, not a guessed action.
- All notes: add cardinality control, EMF vs direct API/agent, log classes, subscription encoding/recursion/retry, query scan limits, alarm M-of-N and notification/runbook tests, dashboard variables/account/Region settings and trace correlation. Cross-account observability and log centralization must be distinguished.

Source conflicts/remaining verification, not confirmed facts:

- Subscription quota pages currently disagree: [user guide](https://docs.aws.amazon.com/AmazonCloudWatch/latest/logs/Subscriptions.html) says five filters; [CLI reference](https://docs.aws.amazon.com/cli/latest/reference/logs/put-subscription-filter.html) says two. The notes say three and also call it both adjustable and hard. Record a source/date and resolve with the applicable service quota instead of copying either number as universal truth.
- The monitoring hub's sub-second metric claim conflates classic custom metrics with newer OpenTelemetry metrics. The current [concepts guide](https://docs.aws.amazon.com/AmazonCloudWatch/latest/monitoring/cloudwatch_concepts.html) distinguishes their resolution/rollup behavior. Teach both explicitly before making a universal one-second statement.
- Alarm delivery retry, alarm-period validation, composite depth, Logs query-result limits, event-size/log-event quotas, EventBridge service-event fees, and OAM actions need direct contracts. “AWS automatically rounds period=1 to 10,” “SNS failures silently never retry,” and the fabricated-looking EventBridge fee recalculation should remain flagged until verified.
